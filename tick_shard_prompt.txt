## Job
1. Read $SHARD_FILE (JSON array of messages). Empty → print "shard empty" and exit.
2. For each message: if it's a real bond deal post, run SIX checks per RULES_COMPACT.md (headline, body, tranche form, deal flags, priced-deal form, sweep). If tender/LM/non-deal → skip.

**CRITICAL — always fetch the full news record:** `search <term>` returns a summary that does NOT include `tranches[i].figi` or other tranche-level fields. For every real deal, you MUST call `news <cat> <id>` to get the full record before checking tranche form fields. Never mark Clean without having called `news` and explicitly checked `tranches[i].figi` for each tranche.
3. Post finding via slack_post.py. React on original message with slack_react.py per these rules:

**FIGI handling — softer treatment so FIGI noise doesn't mask real errors:**
- A missing `tranches[i].figi` (tranche form) or `pricedDeals[i].figi` (priced form) is NEVER treated as a defect that makes a deal "flagged". Always evaluate the rest of the deal on its own merits.
- **FIGI missing, no other errors** → post a CLEAN message (`:white_check_mark:` header) but append a FIGI section after the clean line; react with `double-tick` AND `figi`; tag the Bloomberg terminal users (NOT the associate):
  ```
  :white_check_mark: BR QA — id `<id>` at <stage> — Clean
  <@U09GENPJNQ5> <@U09GGGDB286>
  tranche FIGI not populated
  Fix:
  • tranches[A].figi — null → populate with Bloomberg FIGI for <Issuer> <CCY> <tenor> notes.
  _(automated · BR QA Checker)_
  ```
- **FIGI missing + other real errors** → post a single message with TWO visually separate sections: (1) normal flagged section (associate tag + warning header + non-FIGI Fix bullets + automated footer); (2) blank line then FIGI section (Bloomberg terminal tags + "tranche FIGI not populated" + FIGI Fix bullet, no second footer). React with `exclamation` AND `figi`. Example:
  ```
  <@ASSOCIATE>
  :warning: BR QA — id `<id>` at <stage> — <summary>
  Fix:
  • <non-FIGI fix bullet(s)>
  _(automated · BR QA Checker)_

  <@U09GENPJNQ5> <@U09GGGDB286>
  tranche FIGI not populated
  Fix:
  • tranches[A].figi — null → populate with Bloomberg FIGI for <Issuer> <CCY> <tenor> notes.
  ```
- **FIGI populated, no errors** → normal clean post, `double-tick` only.
- **FIGI populated, other errors** → normal flagged post, `exclamation` only.

Bloomberg terminal user IDs to tag when FIGI missing: `<@U09GENPJNQ5>` (Bloomberg - IG Europe) and `<@U09GGGDB286>` (Bloomberg - EM). Always tag both regardless of deal category.

**NEVER react with `white_check_mark` — that emoji only appears in the post TEXT, it is not a reaction to add.**
For all non-FIGI verdicts: clean → `double-tick` ONLY, flagged → `exclamation` ONLY, skipped → no react.
4. Write each result to $STATE_DELTA_FILE as `{ts: {checked_at, verdict}}`. Never touch state.json directly.

Note: a message may already have a mechanical pre-check flag posted in its thread (tagged `· pre-check)` - e.g. a missing FIGI). That's a separate, narrower pass - it does NOT mean this message has already been fully QA'd. Always run your own complete six-check walk regardless, and post your own separate finding as normal (slack_post.py won't block you on the pre-check's post specifically). You don't need to re-flag the exact same mechanically-covered field again if you also happen to notice it - just don't skip checking everything else because a pre-check flag already exists.

**Multi-tranche deals — do not stop once you find one issue.** A real miss: a ratings error was found on Tranche A of a 3-tranche deal, and Tranche C's wrong reoffer price was never checked because the walk effectively stopped being thorough once Tranche A's issue was found. Before concluding, explicitly check EVERY tranche's priced-deal record (fpr/spread/yield/isin/figi/bloombergCode/ratings/additionalInfo/tier/banks) against that SAME tranche's own source line - finding a problem on one tranche is not a reason to check the others less carefully. If it helps you stay thorough, work through tranches in a literal list (Tranche A: ..., Tranche B: ..., Tranche C: ...) before writing the final post, even though the post itself stays short per the output format below.

## Output format — Slack posts MUST be SHORT

CLEAN (no @-mention):
```

_(automated · BR QA Checker)_
```

FLAGGED (tag reactor first line):
```

_(automated · BR QA Checker)_
```

No walk dumps, no body quotes, no verbose output. End with one summary line: `Shard: N messages, X clean, Y flagged, Z skipped`.
